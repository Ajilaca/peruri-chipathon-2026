## 1. Why NUM_LANES > 1 was UNKNOWN before
Status was UNKNOWN, not FAIL and not a timeout: the base case (depth 6) passed and the induction step
failed on `assert (!bank_overflow_o)` within seconds.

Trace analysis (C2, L=2, yosys-slang frontend, induction step 5): `state_q`=S_RUN, NTT, `layer_q`=0,
`t_q`=0 - the first cycle of every NTT - with the four port addresses 0, 128, 64, 192 exactly as
scheduled. The `bank_map_rom` instance for port 0 received address 0 but output bank 1; the RTL source
says `8'd0: bank_o = 1'd0` and `tb/mem/bank_model.py` agrees. The same FSM state passes in the base
case. So in the formal model the ROM output was not a pure function of its address.

Root cause: Yosys's `proc_rom` pass converts `bank_map_rom`'s 256-entry `case` (one per port) and
`twiddle_rom` into `$mem_v2` memory cells. Memory contents are *state* to the solver. In the base case
they are pinned to their initial values; in the induction step the solver may start from any state, so
it picks ROM contents that are not the real table and "finds" an overflow. That counterexample is an
**unreachable state** (a ROM whose contents differ from its constants): a formal-harness artefact, not
an RTL problem, not a reset problem, not an over-strong assertion.

Fix (harness only): `memory_map -rom-only` after `prep`, which maps ROMs back to constant logic. This
states a design fact (ROM contents are constants), not an additional assumption. The native
`read -formal` flow shows the same behaviour (L=2 passes with the same line), so the earlier
description - "a `-formal` reader artefact on the 256-entry case ROM" - had the right location but the
wrong mechanism, and the `t_q`/`layer_q` invariants added at the time did not address it.
L=1 passed all along because with only 2 ports the 2-accesses-per-bank capacity cannot be exceeded
whatever the ROM contains.

Separately, the flow now uses the yosys-slang frontend because the native `read -formal` leaves
`ntt_pkg`'s `add_mod`/`sub_mod` results undriven (`k1_experiment.md`, caveat 4). The formal
tops' `initial assume (!rst_ni);` was rewritten as an equivalent first-cycle flag register, which that
frontend accepts.

## 3. What these proofs do and do not establish
Proven, for C2, C2-K2 and C2-K2-K1 at NUM_LANES = 1, 2, 4, 8 (k-induction, depth 6):
- `bank_overflow_o` is never asserted (never more than 2 accesses to one bank in a cycle);
- the FSM handshake: one cycle after `busy_o` drops, `done_o` is 1;
- `t_q` and `layer_q` stay within their ranges.
Phase 1 (C0) and Phase 2 (C1) FSM-safety proofs and the Phase 2 bank-map own-pair proof still pass
under the same flow, so their earlier PASS results stand.

NOT established by these proofs: NTT/INTT bit-exactness of the core, memory data integrity, liveness
(that `done_o` is eventually reached), or address-range properties. Bit-exactness rests on the cocotb
regressions (two simulators) and, for the K1 butterfly, on the equivalence evidence
(`k1_equiv_abstraction.txt`, `k1_exhaustive_equivalence.txt`).
