# Phase 9b: hash wrapper (G, H, J) and the FO comparison / selection — test plan and pass rule

Written 2026-10-03, **before any 9b RTL and before any 9b measurement**. Scope: `evidence/phase09/phase9_plan.md` block 9b (and its Amendment A1); FIPS 203 Section 4.1 (H = SHA3-256, J = SHAKE256 with 32 bytes of output, G = SHA3-512) and Algorithm 18 lines 6-12 (ML-KEM.Decaps_internal: K', r' = G(m' || h); K_bar = J(z || c); c' re-encryption; implicit rejection). Golden: `tb/golden/primitives.py` (`H`, `G`, `J`, unmodified, they use `hashlib`) and `tb/golden/mlkem.py` (`ml_kem_decaps_internal`, unmodified). Labels: MEASURED, INFERENCE, ESTIMATE, NOT MEASURED, perhitungan tim. The mathematics is locked (C1).

## 1. What is built
- `rtl/mlkem/mlkem_hash.sv` (parameter `CORE_R2`: 1 the C5 sponge `keccak_sponge_r2`, the default by ADR 0027; 0 the K0 sponge `keccak_sponge`, same ports): input `start_i`, `sel_i` (0 H = SHA3-256, 1 G = SHA3-512, 2 and 3 J = SHAKE256 with the first 32 bytes), `len_i` (message bytes, public), a 64-bit word stream (`in_valid_i`, `in_ready_o`, `in_data_i`; byte k of word w is message byte 8w + k; bytes past `len_i` in the last word are ignored by the sponge); output the digest as a 64-bit word stream (`out_valid_o`, `out_ready_i`, `out_data_o`, `out_last_o`): 4 words for H and J, 8 words for G, word 0 holds digest bytes 0-7 (little endian). `busy_o` from `start_i` to `done_o`; `done_o` is one pulse after the last digest word was accepted and the sponge is idle again. `start_i` is accepted only when idle. For J the wrapper stops the SHAKE256 squeeze after the 4th word (`stop_i` of the sponge, which wipes the state); for H and G the sponge returns to idle and wipes its state by itself. Reset: asynchronous, active low, on the control state.
- `rtl/mlkem/mlkem_fo_cmp.sv` (parameter `WORDS`, default 136 = 1,088 bytes / 8): input `start_i` (accepted only when idle), `WORDS` beats on `in_valid_i` / `in_ready_o` carrying `a_data_i` (c) and `b_data_i` (c'), and the two candidate keys `kgood_i` (K') and `kbad_i` (K_bar), 256 bit each, which must be valid in the cycle of the last accepted beat. The comparison ORs the XOR of all beats: no early exit, no branch on data. After the last beat `done_o` pulses once, `neq_o` = 1 if c != c', and `k_o` = `kbad` if `neq_o` else `kgood`, formed with a 256-bit mask (`(kgood & ~m) | (kbad & m)`), registered and held until the next start. The number of beats and the cycle count depend only on the handshake, never on the data.
- `rtl/mlkem/mlkem_hash_fo_top.sv`: Quartus and test top with both modules side by side (no logic between).
- Not built here: the message assembly, the buffers and the order of the operations (9c); the FIPS 203 input checks (ADR 0031).

## 2. Golden model
The golden is the unmodified `primitives.H`, `primitives.G`, `primitives.J` and `ml_kem_decaps_internal` (their `hashlib` core was checked against the official vectors in Phase 0). `tb/golden/fo_model.py` (new) states the selection in the form of the hardware (`fo_select(c, c_prime, k_good, k_bad)`: mask select with the OR of the XORs) and `tb/golden/tests/test_fo_model.py` checks it against `ml_kem_decaps_internal`: (a) the selection function alone, for a fixed ciphertext and each of its 8,704 single-bit changes (c' differs from c in exactly one bit) the result is K_bar, and for equal ciphertexts it is K'; (b) end to end, a Decaps built from the unmodified golden steps (K-PKE decrypt, G, J, K-PKE encrypt) with `fo_select` as the last step equals `ml_kem_decaps_internal` for a valid ciphertext and for 40 ciphertexts changed in one random bit (each needs a full re-encryption in Python, so not all 8,704).

## 3. Corner cases
- Hash: the four lengths of the algorithms (33: `d || 0x03`; 64: `m || h` and `m' || h`; 1,184: `ek`; 1,120: `z || c`) with their modes; message lengths at the rate boundaries of each mode (SHA3-256 and SHAKE256 rate 136; SHA3-512 rate 72): 0, 1, 7, 8, 9, 71, 72, 73, 135, 136, 137, 143, 144, 271, 272, 273, and random lengths up to 300; garbage in the unused bytes of the last word.
- Hash: input gaps and output back pressure (always, random p = 0.5, long low runs); `start_i` while busy ignored; `sel_i` / `len_i` changed while busy ignored; reset in the middle then a clean run; a J run followed at once by H and G (no state left in the sponge: the digests of the next runs equal the golden).
- Compare: equal inputs; every one of the 8,704 single-bit differences (136 words x 64 bits) in `b_data_i` (c' differs from c in exactly one bit); differences in the first beat only, the last beat only and in all beats; `kgood` / `kbad` all-zero, all-one and random (the 256-bit mask select, including keys that are bitwise complements); input gaps; `start_i` while busy ignored; reset mid-run; the result held after `done_o` while the inputs change.
- Constant cycles: the cycle count of a hash run (always-ready sink, no input gaps) is identical for every data value of one (sel, len); the cycle count of a compare run is identical for equal and for differing inputs and for a difference in the first or the last beat.

## 5. Pass rule (fixed before measuring; no tolerance)
9b is PASS only if: 1. V1-V8 pass on both simulators and every control of V7 fails as required; 2. V9: the fit succeeds and timing is met at 40.000 ns at every seed; 3. resources, Fmax (median of the lowest slow-corner Fmax over seeds 1-6) and the cycle tables are reported as MEASURED. No alternative is chosen in this block; the sponge core of the hash instance (C5 or K0) is reported with both measurements and left as a team choice (PENDING item opened if the team wants to change the default of ADR 0027).

## 6. ESTIMATE written before measuring (not measurements)
- Hash cycles (perhitungan tim, from the sponge: 14 cycles per permutation for C5 and 26 for K0, one input word per cycle): H(ek) with 1,184 bytes = 148 words and 9 permutations: about 148 + 9 x 14 + 10 = 290 cycles (C5); J(z || c) with 1,120 bytes = 140 words, 9 permutations: about 280; G(m || h) with 64 bytes: about 8 + 14 + 10 = 32; G(d || 3): about 30. For K0 the permutation term is 26 instead of 14.
- Compare: `WORDS` + 3 = about 139 cycles.
- Resources: the hash instance is a second sponge: about the ALM of the sponge alone (C5: 6,167 ALM at 8a, K0: 3,572 ALM at 7; both MEASURED earlier, kernel-only), plus a few tens of ALM for the wrapper; the compare holds a 256-bit key register, a 64-bit OR accumulator and a counter: of the order of 400 registers (INFERENCE; no figure claimed). Fmax: not predicted.

## 8. Amendment A1 (2026-10-03, written after the first runs; the pass rule of section 5 is unchanged)
1. **Formal of the hash wrapper uses a protocol stub of the sponge (V8):** with the real C5 sponge (1,600-bit state) inside, the first proof run of `mlkem_hash` was still at induction step 20 after 30 minutes and was stopped (by process id). The proof now replaces `keccak_sponge_r2` by `formal/phase09-integration/9b/keccak_sponge_r2_stub.sv`, which keeps only the protocol the wrapper relies on (start while idle, a free number of cycles before the squeeze, a held digest word, 4 or 8 words and idle in the next cycle for SHA3, words until `stop_i` for SHAKE, `stop_i` reaches idle in the next cycle). The sponge's own control is covered by the Phase 8a formal run (K1-K5; K4 held word, K5 stop) and its digests by simulation against hashlib. The comparison module is proved as it is (no stub).
2. **A vacuous first proof, found and discarded:** the first stub declared its free signals as `(* anyseq *) logic` and read one of them (`f_go`) only inside a clocked `case`; the proof then returned PASS within seconds. A cover check showed that the squeeze state and `done_o` were never reached: the proof was vacuous, the tool treats that variable as a constant (INFERENCE: the attribute on a `logic` that is read only in procedural code is not honoured by yosys-slang; the free signals of the stubs of Phases 3 and 8c are read in continuous assignments only and are free, see `formal_vacuity_check.md`). The signals are now `wire`, cover statements (`mlkem_hash_formal_top.sv`, `mlkem_fo_cmp_formal_top.sv`) and cover-mode `.sby` files were added and are part of the runner (group C: all covered states must be reached), and the proofs and the controls were rerun. The induction then needed supporting invariants relating the stub's state to the wrapper's counter and mode (in the formal top); no property was weakened.
3. **A control that did not compile on Icarus:** the first text of NC-EARLY used a wire before its declaration (accepted by Verilator, rejected by Icarus, which aborted the Icarus run at that control). The mutation now writes the expression out; all runs reported in the evidence were made after the change.
4. **ESTIMATE check (section 6):** hash cycles MEASURED (C5) 30 (G of 33 bytes), 33 (G of 64 bytes), 282 (H of 1,184 bytes), 274 (J of 1,120 bytes) against the ESTIMATE of about 30, 32, 290, 280; compare MEASURED 137 against about 139; K0: 42, 45, 390, 382. Resources: the hash wrapper with the C5 sponge plus the comparison MEASURED 6,745 ALM at seed 1 (median 6,734.5), against the C5 sponge alone at 8a (6,167 ALM): the wrapper and the comparison add about 570 ALM (INFERENCE, the two compiles differ in more than that); with the K0 sponge 4,221 ALM (seed 1) against 3,572 ALM of K0 at Phase 7.
