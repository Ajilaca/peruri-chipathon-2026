# Phase 6: NTT scheduling at operation level — test plan

Written 2026-10-03, **before any Phase 6 RTL and before any Phase 6 measurement** (CRG-4). Scope: `docs/ROADMAP.md` Phase 6, ADR 0024 (Accepted: Phase 6 now, S10 afterwards). Labels: MEASURED,
INFERENCE, ESTIMATE, NOT MEASURED. Working assumptions stated in ADR 0024 (the team may overrule them): NTT/INTT core = S7 (`rtl/ntt/ntt_core_s7_p7.sv`, ADR 0021 still Proposed); full ROADMAP scope.

## 1. What is built
A K-PKE arithmetic unit that runs the polynomial arithmetic of K-PKE.KeyGen (Alg. 13 lines 16-18), K-PKE.Encrypt (Alg. 14 lines 18-21 without compression and encoding) and K-PKE.Decrypt
(Alg. 15 lines 6 without compression) as a fixed program of polynomial operations. Inputs that later come from Keccak and the samplers (matrix Â, s, e, y, e1, e2, the decompressed message
μ, u', v') are written by the testbench; nothing about Keccak, sampling, compression or encoding is in hardware (ROADMAP "not allowed yet").

| Block (new files) | Function |
|---|---|
| `rtl/sched/poly_store.sv` | NPOLY = 24 polynomial slots, each 128 words of a coefficient pair (even and odd halves stored as two 12-bit arrays); two synchronous read ports, one write port with per-half enables; one testbench port (used only when idle) |
| `rtl/sched/gamma_rom.sv` (generated) | γ_i = ζ^(2·BitRev7(i)+1) mod q, i = 0..127 (FIPS 203 Alg. 11), generated by `scripts/gen_gamma_rom.py` from `tb/golden/primitives.py` |
| `rtl/sched/pwm_unit.sv` | BaseCaseMultiply-accumulate, one coefficient pair per cycle: c0 = acc0 + a0·b0 + a1·(b1·γ), c1 = acc1 + a0·b1 + a1·b0 (mod q); five Barrett multipliers (`modmul_barrett`, 3 cuts each), fixed latency |
| `rtl/sched/kpke_sched.sv` | Sequencer: program ROM per operation, op engines XFER (store -> core host port -> NTT/INTT -> back), PWM (first / middle / last pass with a 128 x 24-bit accumulator), ADD, SUB; transform counters |
| `rtl/sched/kpke_sched_top.sv` | Quartus top: sequencer + store + PWM + the S7 core |

Programs (slot numbers; Â[i][j] in slot 3i + j for both KeyGen and Encrypt; temp slot 15):
- KeyGen: NTT s (9-11), NTT e (12-14); for i: PWM Â[i][j] ∘ ŝ[j] over j into 15; ADD 12+i = 15 + 12+i (t̂ replaces ê). Counts 6 NTT / 0 INTT / 9 PWM.
- Encrypt: NTT y (9-11); for i: PWM Â[j][i] ∘ ŷ[j] into 15; INTT 15; ADD 12+i = 15 + 12+i (u replaces e1); PWM t̂[j] (16-18) ∘ ŷ[j] into 15; INTT 15; ADD 19 = 15 + 19; ADD 19 = 19 + 20 (μ). Counts 3 / 4 / 12.
- Decrypt: NTT u' (12-14); PWM ŝ[j] (9-11) ∘ û'[j] into 15; INTT 15; SUB 19 = 19 − 15 (w replaces v'). Counts 3 / 1 / 3. Decaps = Decrypt + Encrypt: 6 / 5 / 15.

## 2. Golden model first
`tb/golden/kpke_sched_model.py`: the same programs on Python slots with the golden `ntt`, `intt`, `multiply_ntts`; checked **end to end against the unmodified golden K-PKE** (`tb/golden/kpke.py`):
KeyGen t̂ equals `byte_decode(12, ek_PKE)`; Encrypt u, v compressed and encoded equal the ciphertext of `k_pke_encrypt`; Decrypt w compressed equals the message of `k_pke_decrypt`, for random seeds.
`tb/golden/op_counts.py` reproduces the ROADMAP counts (done: KeyGen 6/0/9, Encaps 3/4/12, Decaps 6/5/15).

## 3. Corner cases (enumerated before the tests)
- γ ROM: all 128 entries (generated, checked against the golden list); pairs i = 0, 63, 64, 127.
- PWM: all-zero and all-(q−1) operands (largest products, accumulation over three passes with every term q−1); FIRST pass with a nonzero stale accumulator (must be ignored); in-place ADD / SUB (dst = a or b).
- XFER: the core's read latency (4 for S7) at the first and last coefficient; start right after the last host write (the core's write guard).
- Constant cycles: same program cycle count for every input (random seeds, all-zero, all-(q−1)); no data-dependent branch, address or loop count in the sequencer.
- Reset in the middle of a program; start while busy is ignored; testbench writes while busy are ignored.

## 5. PASS criteria (ROADMAP Phase 6) and expectation
- Bit-exact (V2, V4, V5); counts match; cycles constant and recorded per program; Quartus evidence recorded. No adoption rule: Phase 6 adds a block, it does not replace one.
- ESTIMATE (written before measuring): per transform about 256 (load) + 120 (core) + 260 (read back) cycles, per PWM or ADD about 128 + latency; KeyGen about 6 x 640 + 9 x 140 + 3 x 130, i.e. about 5,700 cycles;
  data movement through the core's single-coefficient host port dominates. DSP +10 (five Barrett multipliers), storage 24 x 256 x 12 = 73,728 bits (M10K if the tool infers it; flip-flops otherwise).
  Fmax: not expected to rise (INFERENCE); a new path may lower it.
